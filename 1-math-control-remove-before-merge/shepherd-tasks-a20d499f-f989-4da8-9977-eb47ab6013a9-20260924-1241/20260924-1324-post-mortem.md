## Section 8: Observations and Recommendations

### 8.1 What Worked Well

- **Stage separation was effective.** Stage 30 prevented a contract defect from reaching review, while stage 40 handled review identity, head binding, final gates, and merge.
- **Evidence was head-specific.** After CCA changed [#4](https://github.com/edburns/edburns-dd-3068633-linux-x64-03/pull/4), the shepherd rebuilt validation rather than reusing stale results.
- **Review requests were explicit and verifiable.** Both CCRA reviews were tied to current heads and returned zero findings.
- **The implementation sequence remained serial.** [#3](https://github.com/edburns/edburns-dd-3068633-linux-x64-03/issues/3) did not start until [#4](https://github.com/edburns/edburns-dd-3068633-linux-x64-03/pull/4) was merged into the base.
- **Control-mode isolation held.** Lesson propagation stayed off, and the empty campaign lesson file did not influence the second task.

### 8.2 What Could Improve

- Phase-1 command compatibility checks were incomplete: unsupported `gh pr view --comments --json` combinations were attempted repeatedly.
- Campaign metadata discovery assumed the metadata directory was available through a repository contents endpoint before checking whether it was committed at that branch.
- Token telemetry retained numeric totals but redacted the category labels needed to distinguish input from output.
- The first task consumed 72% of active session time (25m 15s of 35m 11s), primarily because the initial CCA implementation and test encoded an unstated ceiling.

### 8.3 Actionable Recommendations

1. **Add a GitHub CLI compatibility helper.** Centralize PR comments/reviews retrieval through `gh api` or a version-tested command, and prohibit the incompatible `gh pr view --comments --json` combination in stage-30 instructions.
2. **Make metadata lookup source-aware.** Check local campaign metadata first, then query the base branch only when the directory is expected to be committed; emit a single clear diagnostic when it is intentionally external.
3. **Strengthen issue prompts against invented constraints.** For unbounded contract domains, explicitly state “do not introduce an arbitrary upper bound” and require a representative value beyond common guessed caps.
4. **Preserve safe token category labels.** Keep `gen_ai.token.type` visible as `input` or `output` while redacting content and identifiers, enabling direct campaign comparisons.
5. **Record structured phase outcomes.** Add a compact per-session summary artifact containing issue, PR, start/end, review rounds, findings, remediation cycles, tests, checks, tokens, and result. This would avoid reconstructing metrics from verbose Markdown transcripts.
6. **Retain the current head-binding gates.** The checks that bind CI and CCRA evidence to the final SHA were decisive and should remain mandatory.

### 8.4 Control-Campaign Interpretation

This run is a useful `lessonPropagation: off` baseline: both tasks completed with clean CCRA reviews and no propagated campaign lessons. The second task was substantially faster than the first, but the evidence does not attribute that difference to lesson propagation; it is consistent with the first task's one-off remediation and the second task's smaller convergence path. Treatment/control comparisons should therefore use multiple campaigns and separate remediation time from ordinary implementation time.
